# Traffic Demand Prediction - Gridlock Hackathon 2.0

## 🎯 Project Overview
This repository contains the source code and methodology for the HackerEarth Traffic Demand Prediction challenge. The objective is to accurately forecast traffic demand across various geographical locations (`geohash`) based on temporal data, weather conditions, road types, and other environmental factors.

## 🧠 Methodology & Approach
Achieving a high-accuracy prediction required moving beyond basic regression and implementing robust Feature Engineering and Ensemble Modeling. Below is a detailed breakdown of the approach taken:

### 1. Advanced Feature Engineering
To help the model understand complex temporal and spatial patterns, the raw data was transformed into mathematically meaningful features:

- **Cyclical Time Transformation:** Raw timestamps (e.g., "23:45" and "00:15") are difficult for tree-based models to interpret as continuous events. To solve this, time was converted into total daily minutes and mapped onto a circle using Sine and Cosine trigonometric functions. This ensures the model mathematically understands that late night and early morning are sequentially next to each other.

- **Smoothed Target Encoding (Geohash):** The `geohash` feature is highly cardinal (contains thousands of unique locations). Standard ordinal encoding is inefficient here. Instead, Target Encoding was utilized. Each `geohash` was replaced with its historical average traffic demand. A smoothing factor (weight) was applied to prevent overfitting on locations that had very few historical data points, pulling them closer to the global mean.

- **Frequency Encoding:** The total historical frequency of each `geohash` was calculated to give the model a quantitative sense of how "busy" or common a specific location is within the dataset.

### 2. Data Preprocessing
- **Missing Value Imputation:** Missing categorical variables (such as `Weather`, `Landmarks`, or `RoadType`) were explicitly filled with a `Missing` placeholder. This allows the model to learn if the absence of data correlates with traffic demand.

- **Robust Categorical Encoding:** The `OrdinalEncoder` was strictly configured to handle unknown values gracefully (`handle_unknown='use_encoded_value'`). This guarantees that if the test set introduces a completely new location or weather condition not seen during training, the pipeline will not break.

### 3. Modeling Strategy
- **Core Algorithm:** `LightGBM` (Light Gradient Boosting Machine) was selected as the primary estimator. It builds trees highly efficiently, natively handles missing values, and is the industry standard for tabular data regression tasks.

- **K-Fold Cross Validation & Ensembling:**
  - A 5-Fold Cross-Validation strategy was implemented.
  - The training data was split into 5 distinct folds.
  - Five separate `LightGBM` models were trained, each learning from a different subset of the data and validating on the remainder.
  - The final predictions are the averaged predictions of all 5 models. This ensemble technique drastically reduces variance, minimizes overfitting, and results in a highly robust predictive engine.

## 🚀 How to Run the Code
1. Ensure Python 3.x is installed.

2. Install the required dependencies:

```bash
pip install pandas numpy scikit-learn lightgbm
```

3. Place `train.csv` and `test.csv` inside a folder named `dataset`.

4. Execute the Python script or notebook.

The script will automatically perform feature engineering, train the 5-fold ensemble, and generate the final `submission.csv` inside the `dataset` folder.
